## 四、桌宠形象：高精度毛茸茸萨摩耶

这是本项目最核心、最不能妥协的部分。

### 4.1 角色视觉风格

设计一只辨识度极高的卡通萨摩耶：

- 毛发以自然的乳白色、暖白色为主，具有柔软的层次感。
- 具有萨摩耶标志性的微笑表情、黑色鼻头、明亮眼睛和立耳。
- 脸部饱满，耳朵内侧带有微弱的暖粉色。
- 身体圆润、自然，四肢与尾巴具有符合犬类解剖结构的比例。
- 尾巴毛茸茸并自然上卷。
- 毛发具有真实的体积感和细腻的光影，而不是单纯使用白色轮廓。
- 支持眨眼、耳朵摆动、毛发轻微起伏、尾巴摇动及呼吸动作。

整体审美可以向高质量动画电影角色、精品 3D 手办以及精致的治愈系游戏角色靠近。

建议优先考虑风格化 3D 角色、预渲染高质量动画序列，或者高质量 2.5D 多层角色动画方案。

技术选择应兼顾不同手机的 GPU 性能和悬浮窗运行效率。

### 4.2 角色资源制作要求

必须建立统一的角色形象规范，避免不同动作中的狗看起来像不同的角色。

角色在站立、行走、转身、跳跃、坐下、躺下时，应保持一致的身体比例、毛发风格、脸部特征和光照逻辑。

不要使用从网上随意下载的低质量动图，也不要用多个风格不一致的 GIF 拼接。

如果需要借助生成式工具制作模型、贴图、插画或动画资源，可以使用合理的工具链，但必须检查素材质量、版权及许可，并将可再生成或可编辑的源资源纳入仓库。

**角色素材质量不过关时，不允许仅靠增加功能数量掩盖画面质量问题。**

## 五、动画与生命感系统

请不要简单设计成几个动作轮流随机播放。

我希望你实现一套具有明显生命感的宠物行为系统。

### 5.1 动作库

至少围绕以下动作族设计并尽可能完整实现：

**日常状态**

站立、坐下、趴下、侧躺、蜷缩、睡觉、醒来、伸懒腰、打哈欠、摇尾巴、轻微呼吸、眨眼、左右张望、歪头、挠痒、舔爪、整理毛发。

**移动状态**

缓慢走路、轻快小跑、加速奔跑、原地蹦跳、向前跳跃、转身、后退、短暂停步、滑步纠正、落地缓冲、身体回弹。

**情绪状态**

开心微笑、吐舌、兴奋、撒娇、好奇、困倦、委屈、害羞、期待、放松、受到惊吓、获得安抚、注意力集中。

**互动状态**

接受摸头、主动蹭手、追随手指、抬爪打招呼、翻肚皮、请求抚摸、接住零食、玩玩具、寻找用户、回应呼唤。

这些是目标动作范围，而不是允许你用几个通用动画替代全部状态。

### 5.2 动画状态机

采用分层状态机、行为树、效用 AI 或其他成熟的行为控制方法。

应区分：

- 基础姿态
- 移动动作
- 情绪状态
- 注意力目标
- 用户交互反应
- 环境事件
- 长期行为倾向

动作之间必须具备合理的过渡。

例如：

小狗正在走路 → 发现用户摸头 → 减速停止 → 抬头 → 眯眼 → 摇尾巴 → 吐舌 → 结束互动后恢复自然状态。

严禁直接从奔跑瞬间切换到静止睡觉，或者在不同动作间产生瞬移、明显变形和不自然的姿态跳变。

需要特别重视：

- 动作混合与过渡
- 加速和减速曲线
- 起跳与落地
- 耳朵、尾巴、毛发的次级运动
- 角色运动方向
- 遮挡关系
- 阴影与接触感
- 长时间运行时的动作多样性

### 5.3 行为自主性

小狗应该具有一定自主性，但不能频繁打扰用户。

例如：

它可能突然伸懒腰，也可能在屏幕边缘坐下观察用户；偶尔跑一小段路后趴下；很久没有互动时，偶尔抬头看看用户。

使用概率与上下文共同驱动行为，而不是简单的固定定时循环。

对相似动作设置冷却时间，对复杂行为设置打断和恢复策略，避免机械重复。

支持安静模式、活跃程度和不同时间段的行为调整。

## 六、与手机桌面的空间交互

桌宠应当能够出现在 Android 手机桌面及用户授权的其他应用上层。

### 6.1 悬浮能力

支持：

- 在桌面上显示
- 根据用户设置显示在其他 App 上层
- 自由拖动
- 自动吸附屏幕边缘
- 调整尺寸
- 调整不透明度
- 设置默认出现位置
- 临时隐藏
- 恢复显示
- 锁定位置
- 控制是否随系统启动
- 从应用或通知入口快速唤出

悬浮窗非交互区域应尽可能允许触摸穿透，不能用全屏透明窗口阻止用户正常使用手机。

必须正确处理状态栏、导航栏、刘海、打孔屏、手势导航和不同分辨率。

### 6.2 跑近与跑远

希望通过角色缩放、运动速度、阴影以及适度的视觉变化，实现一定的空间纵深感。

例如：

小狗从远处跑近时逐渐变大；向远处跑去时逐渐变小。

这一效果必须符合运动逻辑，避免突兀缩放。

### 6.3 与桌面组件互动

尝试实现小狗在桌面图标或组件附近穿梭、绕行、停留、跳跃等行为。

但必须首先调查 Android 官方 API 的真实能力和限制。

普通第三方应用未必能够可靠读取其他 Launcher 的图标布局、组件边界或任意应用内部控件位置。

因此必须采用分层方案：

1. 优先实现系统允许的、安全可靠的屏幕区域感知及避障。
2. 如果无法识别真实图标位置，可通过用户可配置的活动区域、禁止区域或自主提供的桌面小组件实现空间交互。
3. 如果需要更深层的桌面集成，可以把可选的自定义 Launcher 或配套 Widget 作为扩展模块。
4. 不允许为实现视觉效果而滥用无障碍服务或进行隐私敏感的屏幕监视。

对于不能跨 Launcher 保证的功能，必须明确界定支持范围。

## 七、自然直觉的触摸交互

交互应当简单易学，而不是设计几十种复杂手势让用户记忆。

建议默认采用：

**单击**：唤起注意力，触发自然反馈，并可打开轻量快捷操作。

**短距离轻抚头部**：识别为摸头，触发眯眼、摇尾巴、吐舌或撒娇等反馈。

**长按拖动**：移动桌宠位置。

**点击聊天气泡或快捷入口**：进入与小狗聊天的界面。

**双击**：可配置为召唤、互动或打开快捷功能，但不是必须依赖的隐藏操作。

针对不同的身体区域，可以进一步实现轻抚头部、抚摸背部、碰鼻子等差异化反应。

必须做好触摸命中测试、拖动阈值与手势冲突处理，避免摸头被误识别为拖动。

应提供简短的新手引导，并允许用户在设置中查看和调整手势。

交互反馈除了角色动画，也可以包含可关闭的轻量振动和音效。

## 八、专业级备忘录与智能提醒

点击 CuteDog 应用图标，应进入完整的主应用。

主界面要具有成熟效率工具的操作逻辑和精致质感。

### 8.1 备忘录功能

至少包括：

- 创建、编辑、删除备忘事项
- 设置标题、详细内容和时间
- 设置提醒提前量
- 单次提醒和重复提醒
- 重要程度及分类
- 事项完成、撤销完成
- 逾期事项查看
- 搜索和筛选
- 按日期和优先级排序
- 今天、即将到来、已完成等视图
- 本地持久化
- 可选的数据导入导出

创建提醒应尽量快捷。

例如用户可以输入：

“明天下午三点记得给老师发邮件。”

系统应在能力允许时提取事项内容和时间，展示可确认的编辑结果，而不是未经确认便执行可能错误的提醒。

### 8.2 提醒触发

这是必须可靠运行的业务模块。

指定时间到来时，小狗可以播放一个短动作，并弹出与桌宠风格统一的提醒气泡。

同时必须提供标准 Android 通知作为可靠的基础提醒方式。

提醒交互包括：

- 查看详情
- 标记完成
- 稍后提醒
- 修改时间
- 关闭本次提醒

提醒内容可以采用自然语言，例如：

“汪！你之前说三点要给老师发邮件，我来提醒你啦～”

当通知涉及重要事项时，文字要清晰准确，不得因为宠物语气影响信息可读性。

### 8.3 Android 后台适配

请认真处理 Android 的实际系统限制：

- 通知权限
- 精确闹钟能力与相关授权
- 后台任务限制
- 电池优化
- Doze 模式
- 设备重启后的提醒恢复
- 时区与夏令时变化
- 系统时间修改
- 重复任务调度
- 应用被系统回收
- 悬浮窗权限

不要假设一个普通后台 Service 可以永久运行。

提醒应根据适用条件采用 Android 官方推荐的调度机制，例如 AlarmManager、WorkManager 等。

精确提醒与非精确后台任务需要分别设计。

对于无法保证悬浮气泡出现的场景，必须有可靠的通知降级方案。

## 九、每日一句：至少 365 条不重复的温暖表达

我希望小狗每天都能给我一句富有爱意的表达。

请制作不少于 365 条经过整理、审核和去重的中文短句库，覆盖至少一年。

内容可以包含：

- 温柔的陪伴
- 生活中的小确幸
- 对用户的鼓励
- 温暖的问候
- 有诗意的情感表达
- 关于珍惜与爱的感悟
- 适合不同季节的句子
- 适合生日、节日等特殊日期的句子

可以适当引用处于公有领域的经典诗歌，或在许可允许的条件下使用合规短句。

对仍受版权保护的作品，不要大规模复制诗句。优先使用原创表达、经过准确核实的公有领域文本以及有清晰出处的合法引用。

不要凭空编造诗人名句或错误归属。

### 9.1 每日展示规则

用户每天第一次解锁或首次进入适当使用场景时，小狗可以显示当日句子。

需要研究 Android 对解锁广播、后台弹窗和悬浮窗的限制，采用合规且可靠的实现。

要求：

- 支持关闭每日问候
- 支持调整展示时间
- 支持静音与勿扰时段
- 支持保存喜欢的句子
- 支持重新查看历史句子
- 支持从通知或应用内主动查看

对于没有悬浮权限或系统不允许主动展示的场景，采用通知及下次进入应用时展示的降级策略。

每日问候不应该打断用户的紧急操作。

## 十、情感陪伴智能体：真正可以交流的小狗

这是另一个极其重要的核心模块。

我希望在软件内部拥有独立的聊天界面，可以与小狗通过文字自然交流。

它必须能够理解日常语言、上下文和情绪，以萨摩耶的身份进行温暖、自然、有个性的陪伴式回应。

目标体验接近成熟的中文情感陪伴聊天产品，但不要求在无法满足算力条件时虚假宣称具备相同性能。

### 10.1 角色人格

小狗的性格应当是：

温柔、活泼、善良、可爱、偶尔调皮、善于倾听、富有好奇心。

它可以撒娇，可以关心用户，也可以幽默地回应日常琐事。

但它不能永远只说：

“汪汪，你真棒！”

“主人，我爱你！”

这种重复而空洞的套话。

它应当能够识别不同话题，进行较为深入的上下文对话。

用户分享开心的事情时，小狗表现出喜悦。

用户感到疲惫时，小狗能够提供自然安慰，而不是机械输出鸡汤。

用户谈论学习或工作时，小狗既能保持角色人格，也可以提供实际帮助。

避免过度亲密、情感操纵、鼓励现实社交隔离或让用户依赖应用。

### 10.2 智能体架构

请认真评估以下路线：

A. 设备端运行的小型中文语言模型。

B. 用户可配置的远程大模型 API。

C. 本地小模型与云端模型相结合的混合架构。

D. 对无法提供模型服务的场景设置高质量离线降级。

**优先寻找能够在普通 Android 手机上真正运行的高质量方案，不要盲目声称大型语言模型可以直接内置并流畅运行。**

评估维度必须包含：

- 中文对话质量
- 情绪理解能力
- 上下文长度
- 设备内存占用
- APK / 模型下载体积
- 电池消耗
- 响应延迟
- 网络依赖
- 费用
- 开源许可证
- 用户隐私

如果端侧模型无法满足高质量交流目标，优先设计可靠的可配置模型接口，并明确告知联网对话需要什么条件。

不允许把开发者私人 API Key 硬编码进 APK。

应用应提供清晰的智能体设置界面，允许用户配置或选择支持的服务。

网络失败时必须有明确反馈和可用的离线功能。

不要用关键词匹配、随机句子拼接或者固定模板系统冒充真正的通用智能体。

### 10.3 智能体记忆

希望小狗能够在用户授权下记住部分长期信息。

例如：

用户喜欢什么、正在准备什么事情、最近有什么值得期待的日子。

可以采用短期上下文与长期记忆相结合的结构。

长期记忆必须允许：

- 查看
- 修改
- 删除
- 清空
- 禁用
- 导出

隐私敏感信息应采取本地优先策略，不得未经许可上传。

### 10.4 智能体与角色动作联动

聊天内容应当能够影响桌宠的表现。

例如：

用户表示开心，小狗可以兴奋摇尾巴。

用户表示疲惫，小狗可以坐下来陪伴。

用户说“来抱抱”，小狗可以靠近并做出撒娇动作。

但智能体只能输出经过校验的动作意图，最终由动画系统判断动作是否合法、能否被打断，以及如何自然过渡。

不要允许语言模型直接生成未经验证的动画命令或执行任意系统操作。

## 十一、进一步提升生活感的功能

请在不牺牲主要功能质量的前提下，设计一些真正有价值的扩展。

### 11.1 轻度情绪与习惯系统

小狗可以根据互动、时间段和最近活动，形成轻微的行为变化。

例如：

早晨更加精神，夜晚动作趋于安静。

被摸头后更愿意接近用户。

长时间没有互动时，可以偶尔主动打招呼。

但不要设计会给用户制造愧疚感的饥饿、疾病或惩罚机制。

### 11.2 小狗成长与个性

允许用户为小狗取名字。

可以设置不同的性格倾向，比如安静、活泼或平衡。

随着使用时间增加，小狗可以解锁一些非强制性的动作、玩具或互动。

不要让成长机制影响备忘录和提醒的基本使用。

### 11.3 可选玩具互动

例如：

- 丢球后小狗追逐
- 点击小零食后小狗开心地吃掉
- 小狗偶尔叼着玩具出现
- 小狗在合适时机抬爪打招呼

不要求一次堆积大量小游戏，但优先实现少量具有高动画完成度的互动。

### 11.4 环境与时间感知

在用户授权及技术允许的前提下，结合时间、充电状态、设备音量模式等轻量信息，改变小狗行为。

例如：

手机进入充电状态时，小狗偶尔安静地休息。

夜间自动降低动作频率。

勿扰模式下避免主动发声。

不应要求不必要的敏感权限。

### 11.5 音效与微反馈

考虑设计轻量的犬类叫声、喘息声、脚步声及互动音效。

音效必须可独立关闭，并控制音量、频率和出现情境。

在公共场合默认避免突然发出明显声音。

## 十二、界面与视觉设计规范

我希望这款应用具有顶级的视觉品质，而不是普通 Android 练习项目的默认样式。

### 12.1 视觉方向

整体风格：

**温暖、柔和、精致、现代、具有高级感和细腻的空间光影。**

推荐采用：

- 暖白色
- 奶油色
- 柔和的浅棕色
- 少量清新的强调色
- 适度半透明与磨砂玻璃
- 自然的柔和阴影
- 高质量圆角与层次设计
- 克制的微交互动效

请参考优秀的日程管理应用、任务管理工具以及成熟移动产品的设计逻辑，但不要直接复制其受保护的资源。

### 12.2 主界面信息架构

建议至少包含：

**首页**

展示小狗、今日问候、今日待办与快速入口。

**备忘录**

用于完整管理提醒和事项。

**陪伴聊天**

具有完整对话历史、消息输入、状态反馈及智能体设置。

**小狗与设置**

用于管理桌宠位置、大小、活跃程度、权限、声音、动画质量和其他个性化设置。

请根据实际使用效率优化导航结构，不必僵硬地照搬以上页面划分。

### 12.3 对话气泡

气泡需要具有高度统一的设计语言。

要求：

- 细腻且克制的半透明效果
- 柔和的高光与阴影
- 自然的出现和消失动画
- 合理的文字留白
- 清晰的文本对比度
- 与小狗位置相关的气泡锚定
- 屏幕边缘的自动避让
- 动态调整气泡方向和大小
- 提醒气泡与普通聊天气泡具有视觉上的区别

不要为了追求玻璃质感而牺牲性能和可读性。

### 12.4 完整状态设计

每个关键页面都必须考虑：

加载、空数据、成功、失败、权限不足、网络异常、深色模式、横竖屏变化和字体放大。

应支持 Android 常见无障碍要求，并对动态效果提供降低动画强度的选项。

## 十三、性能与资源管理

桌宠应当可以长期使用，而不是运行几分钟就造成手机发热或严重耗电。

需要针对以下场景建立性能控制策略：

- 用户正在触摸桌宠时
- 桌宠自主运动时
- 小狗静止时
- 屏幕关闭时
- 设备处于省电模式时
- 其他应用处于全屏状态时
- 设备出现内存压力时

建议采用动态帧率、分级动画质量、资源缓存和合理的渲染暂停策略。

追求活动状态下的高流畅度，同时避免在静止或息屏时持续无意义地高帧率渲染。

必须检测：

- 内存泄漏
- 不必要的后台 CPU 使用
- GPU 资源占用
- 网络请求异常
- 动画线程阻塞
- 悬浮窗服务异常恢复
- 大量提醒数据下的性能

不要为每一帧无条件重新分配大型图形资源。

与用户充分说明悬浮窗、通知、精确闹钟和其他权限的用途。

对于 Android 系统禁止或限制的能力，必须采用合规替代方案，不得通过隐蔽方式绕过系统安全机制。

聊天历史、备忘录和长期记忆应当具有可靠的持久化机制。

如果涉及远程 AI 服务，要明确提示数据可能发送给相应服务商。

日志不能包含 API Key、隐私聊天内容或其他敏感信息。
