# CuteDog 智能体设计与验证边界

## 已采用方案

当前实现采用**用户自配 OpenAI 兼容 HTTPS 模型接口**，不内置或下载语言模型。按用户指定，新安装默认填写 `https://api.deepseek.com` 和精确模型名 `deepseek-flash`，只是可编辑的连接预设；不代表项目提供付费额度、账号或 API Key。既有安装已经保存的地址与模型不会被新默认值覆盖。如果服务商不接受 `deepseek-flash`，必须报告真实错误，不能偷偷改成别的模型。真实返回内容来自用户选择的服务商，应用不会用模板、关键词或随机短句冒充模型回答。

`ChatClient`（本地配置/记忆快照） → `ChatRequestFactory`（受控序列化） → `ChatTransport`（HTTPS `POST /chat/completions`） → `ChatReply` → 聊天界面／宠物动作意图。模型请求在线程池执行，与 UI、动画及提醒调度分离；请求由调用方 coroutine 生命周期控制，取消请求会断开连接。

## 路线比较

| 路线 | 中文交流与上下文 | 内存、体积、电量 | 网络、延迟与费用 | 许可与隐私 | 本版本选择 |
|---|---|---|---|---|---|
| A：端侧小模型 | 依模型、量化与设备而异；短上下文和复杂中文能力需要实测 | 约十亿参数量化模型通常仍需数百 MB 至数 GB 额外模型及运行内存；持续推理耗电，不适合轻率打包 | 可离线；速度取决于芯片，不能承诺普通手机实时响应 | 每个权重和运行时需单独核对许可证；数据可本地处理 | 未实现；没有声称支持端侧推理 |
| B：远程可配置模型 | 由服务商与所选模型决定，可使用成熟中文模型；客户端保留有界最近上下文 | APK 不含权重；主要消耗网络与少量 JSON 内存 | 必须联网，存在超时、限流及服务商计费 | 对话发往明确配置的服务商；其保留与训练政策需用户自行确认 | **已实现** |
| C：端云混合 | 本地简单任务与云端复杂交流可互补，但路由和体验一致性更复杂 | 仍需端侧权重、双套推理及模型升级管理 | 可减少部分联网，但不自动消除成本 | 两类模型及其数据流均需审计 | 后续研究，当前未实现 |
| D：离线降级 | 不伪称通用对话；提供明确不可联网／未配置提示 | 无推理负担 | 无模型费用 | 备忘录、短句和宠物互动仍在本地使用 | **已实现错误提示与本地功能保留** |

本表是工程选型判断，不是目标手机上的性能基准。远程模型质量、吞吐和账单由用户选择的服务决定。

## 配置与首次使用

1. 取得支持 OpenAI Chat Completions 的服务地址、模型名称和用户自己的 API Key。
2. 在应用模型设置填写 HTTPS 基地址（当前指定为 `https://api.deepseek.com`）或完整的 `/chat/completions` 地址。
3. 检查服务商、传输内容与费用后保存。在聊天页发送第一条消息。
4. 如果接口报 401/403，检查 Key、账户状态、模型权限；404 检查路径与模型；429 检查限流及额度。请求不会自动重试，以免重复计费。

不支持 HTTP 明文接口；拒绝地址中的用户名、密码、查询参数和片段。HTTP 重定向不会携带 Key 自动跟随，需用户填写最终 HTTPS 地址。证书验证保持平台默认启用；不提供关闭验证开关。

## 上下文、人格与动作

- 最近最多 24 条有效 user/assistant 消息，总计最多 24000 个字符发送给模型。仅移除完整旧消息，不截断用户问题或 Unicode 字符；超出窗口时通过 `contextTruncated` 提醒界面。单条超过窗口的消息明确报错。历史仍保存在本地；超出窗口的旧消息不会自动成为“永久记忆”。
- 昵称取自用户的小狗设置。每轮请求都携带固定的萨摩耶角色设定、问候及安慰的口吻示例和当前昵称。闲聊尽量简短，认真提问时优先给出清楚的回答。
- 模型只能在末尾输出一个动作意图。允许动作在 `ChatPolicy.allowedIntents` 中登记；其他值丢弃。其文本不会成为脚本、反射调用、系统命令或提醒任务。
- 动画控制器最终决定动作是否可执行及如何过渡。模型没有创建提醒、读取其他 App、删除文件或调用系统工具的能力。
- 没有 API Key、网络中断、证书异常、超时和服务错误都会显示明确提示，不插入虚假 AI 回答。

## 记忆与数据

双击桌宠打开互动菜单，或在陪伴页按住麦克风说话。首次使用由 Android 申请麦克风权限。按住时，Vosk 在手机上逐段听写最多 30 秒的普通话，松手确认提交。录音在内存中处理，手指滑出按钮即可取消。用户同意联网对话后，应用才向配置的模型服务发送听写文字。[Vosk 模型](https://alphacephei.com/vosk/models)

桌宠麦克风、桌面聊天小窗和陪伴页共用聊天记录。发送成功进入会话的听写标为「语音输入」，完整的模型回复标为「语音回复」。打开或重新进入任一聊天窗口都可阅读同一段对话。语音播放是否成功独立于文字保存。联网失败时可以对同一条听写重试，取消录音或空白听写不会新增记录。旧版已有消息保留原文。

APK 内置审阅版小萨的 A 声线。开始录音时，后台同时预热朗读模型。连续对话短时复用听写和朗读模型。DeepSeek 流式返回多个分句时，应用可以在收到下一分句的开头时先合成首个完整分句。回复入库并确认开头一致后，播放器即可播放已经生成的音频块，余下的内容边合成边播。较短的单句直接交给播放器，气泡逐字显示正文。不同回复共用审阅版小萨问候中的发音参考。菜单中的「停止播放」或聊天输入栏的「停止朗读」可以打断声音。[本机语音实现](offline-pet-speech.md)

- `companion.db` 保存对话和用户明确编辑的长期记忆；采用 SQLite WAL 与参数化语句。记忆不是自动抓取或提取。
- 长期记忆上传开关默认关闭。用户打开后，当前最多前 20 条、总计 8000 字符的记忆作为单独的低权限用户背景数据发送；不会拼入 system 指令。
- 支持单条聊天删除、完整聊天 JSON 导出，以及查看、编辑、删除、清空和 JSON 导出记忆。关闭记忆上传保留本地记录；清空记忆删除本地记录。清空聊天与清空长期记忆是两项独立操作。
- 普通聊天历史本身也包含敏感内容：发送消息时，有界最近上下文会上传到用户指定接口。不要把本地持久化误解为完全离线。
- API Key 用 Android Keystore 生成的 AES-256-GCM 密钥加密，持久化文件仅保存随机 IV 与密文。系统密钥失效或无法解密时，要求用户重新输入；不回退为明文。
- 设备卸载会移除应用数据；导出的记忆由用户自行保管。应用不提供云同步。
- 删除本地记录不能撤回已经发送到服务商的数据；其删除与保留政策由服务商决定。
- 无聊天、API Key 或原始服务错误正文日志。错误仅显示经过归类的通用说明。

## 请求保护与测试范围

官方 DeepSeek 接口请求 SSE 流。收到的正文按可见字符逐个显示，标点处稍作停顿，尾部动作标记及推理字段不会进入对话气泡。其他兼容接口继续使用普通 JSON，收到后使用同一逐字显示逻辑。用户可以跳过逐字显示。减弱动画或开启触摸探索时完整呈现回复。已有聊天记录直接展示全文。[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)

连接超时 15 秒、单次读取超时 45 秒，总时限 60 秒。普通 JSON 上限 256 KiB，SSE 上限 2 MiB（含事件开销）。完整回复落库后才触发桌宠动作。异常中断的流不写入聊天记录，可重试上一条。桌宠菜单的「聊聊天」在当前桌面上打开可输入的小窗，与应用内陪伴页共用昵称、设置和历史。

测试分层如下，实际通过数量由当次 Gradle/XML 或设备 instrumentation 结果确认：

| 测试类 | 真实检验内容 |
|---|---|
| `ChatPolicyTest` | HTTPS 地址、含凭据地址拒绝、动作白名单、角色过滤、完整消息上下文边界、过长回复明确失败 |
| `ChatRequestFactoryTest` | 模型/Unicode/角色 JSON 序列化、密钥不出现在正文和对象日志、记忆默认不发送/低权限发送、重试绑定用户 ID、不带未来消息、删除后的新请求不包含记忆、上下文裁剪信号 |
| `ChatHttpsTransportTest` | 本地真实 HTTPS POST/Authorization/JSON；拒绝重定向泄露、401/403/404/429/503错误脱敏、非法 JSON/null content/响应上限、读取超时和总期限、取消后不交付迟到回复、默认 TLS 拒绝测试证书、连接失败 |
| `ChatPrivacyPersistenceTest`（Android） | Keystore 加解密、随机 IV 和密文损坏。SQLite 旧版聊天与记忆迁移、语音标记、重复回复和删除后的迟到回复，以及记忆授权对出站载荷的影响 |
| `OfflineVoiceDeviceTest`（Android） | 真实语音样本听写、HTTPS 回答入库与 A 声线朗读、桌面与陪伴页互读、网络失败后的重试 |

HTTPS 回环夹具使用 `src/test/resources/chat/localhost.p12`，由 JVM 测试和独立 Android 测试 APK 使用。设备上的窗口、录音和朗读测试在专用测试模拟器运行。应用的发行 APK 使用系统 TLS 信任，且不含该测试证书。测试问答用于验证传输、界面与播放。[设备上的语音对话测试](../app/src/androidTest/java/com/cutedog/app/voice/OfflineVoiceDeviceTest.kt)

运行方式：

```sh
./gradlew :app:testDebugUnitTest --tests 'com.cutedog.app.chat.*'
./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.cutedog.app.chat.ChatPrivacyPersistenceTest
```

云环境使用 `python3 scripts/cloud-gradle.py` 替代命令开头的 `./gradlew`。

JVM 测试报告在 `app/build/test-results/testDebugUnitTest/`。各版本的窗口、语音和数据迁移验证见[设备验收记录](interaction-review.md)。

**没有服务凭据时，中文对话质量、多轮回复、服务计费、真实限流与端到端联网成功不能标记为通过。** Keystore/SQLite 由独立的 Android instrumentation 测试验证；其实际执行结果见测试报告。HTTPS 取消目前由 JVM 真连接夹具覆盖，仍应验证各 Android 厂商网络栈。纯 JVM 规则测试不能替代设备验证。模型生成文字无法保证总是遵循人格或没有事实错误，应把它视为交流与辅助信息。

## 指定 DeepSeek 服务的真实验收

用户指定地址 `https://api.deepseek.com`，模型 **`deepseek-flash`**。脚本 `scripts/verify-live-ai.py` 默认只显示配置名称/凭据是否存在，不发网络请求：

```sh
python3 scripts/verify-live-ai.py
```

在用户通过环境设置安全配置 `CUTEDOG_DEEPSEEK_API_KEY` 后，才可明确执行：

```sh
python3 scripts/verify-live-ai.py --execute --model deepseek-flash --output artifacts/deepseek-live-verification.json
```

脚本使用现有 HTTPS 代理与系统 CA，不禁用证书校验，不拒绝平台代理的合法凭据占位符，也不会把环境凭据写入 APK。五轮均为公开、虚构、无私人信息的中文测试输入，验证真实接口、两项明确的多轮上下文事实、情绪交流、实用帮助及白名单动作协议；返回质量仍需人工审阅。记录服务请求 ID、准确请求/返回模型、脱敏回复和使用量，遇到拒绝、超时、无效模型立即记录，不自动重试或替换模型。
