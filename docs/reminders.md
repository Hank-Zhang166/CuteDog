# 备忘录与系统提醒

## 实现范围

- `data/ReminderRepository` 使用 Android SQLiteOpenHelper 持久化事项，支持创建、读取、编辑、删除、完成和撤销完成。启用 WAL，索引覆盖完成状态与到期日期。
- `ReminderScheduler` 将提醒注册给 `AlarmManager`。提醒不依赖页面、聊天请求或悬浮服务存活。
- Android 12 及以上有精确闹钟授权时使用 `setExactAndAllowWhileIdle`；无授权或授权在调用期间撤销时使用 `setAndAllowWhileIdle`。降级后时间由系统批处理，**不能承诺准点**。
- 系统通知提供查看详情、完成、10 分钟后提醒、关闭。点击详情进入备忘录；修改时间在应用内完成。
- 已在运行的桌宠接收应用内提醒事件，可显示气泡。提醒广播不会从后台强制拉起桌宠或 Activity；系统通知是基础渠道。
- 设备重启、应用更新、系统时间或时区变化以及精确闹钟授权恢复时，`RestoreReceiver` 重新注册提醒和每日问候。

## 时间与重复规则

单次事项存储时间戳，在更换时区后仍指向同一个时刻，界面按当前设备时区显示。每天、每周、每月重复事项保存创建/编辑时间时选择的设备时区。日/周重复按该时区的日历推进，不以固定 24/168 小时模拟日历，因此一般时刻跨夏令时仍保持当地钟点。

每月重复保存原始日期锚，例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日，闰年二月为 29 日。更改提醒时间时应重置 `anchorDay=0` 并更新 `timeZoneId`；只改标题/详情时保留锚。

遇到夏令时跳过的本地时刻，Java 时间库会将该次前移到有效时刻，下一天恢复保存的原始钟点。遇到回拨导致同一钟点出现两次时采用较早的有效偏移，每周期只提醒一次。自然语言解析器会拒绝显式日期落入不存在的当地时刻。

提醒提前量支持 0–10080 分钟。重复事项触发后排到下一个通知时间在未来的周期；很长时间未使用应用时，不会为每个漏掉的周期发一串通知。逾期单次事项在恢复时补发一次。

重复通知的“完成”结束当次提醒，下一周期继续运行。应用列表对重复事项提供“完成本次”和“结束整组”选择。结束整组可撤销，完成本次会推进下一周期，目前没有恢复已完成历史周期的独立操作。10 分钟后提醒使用独立持久化 `snoozedUntil`，不会覆盖下一周期日期。关闭本次通知不会删除事项或取消未来周期。

## 幂等与并发

每次到期时间先写入 SQLite 持久待投递表（outbox），唯一键为事项编号和周期时间。记录保留标题、详情、原时间、投递状态、失败原因和尝试次数。相同广播只捕获一次；排入下一周期时使用原日期条件更新，避免覆盖用户刚编辑的日期。删除事项会级联删除投递记录。恢复过程能够修复“已捕获周期、还未保存下一次重复日期”的中断。

只有 NotificationManager 调用成功后，记录才更新为 sent。若进程在入表后、发送前崩溃，下次恢复继续发送；若发送后、提交 sent 前崩溃，重试沿用相同通知标识并使用 onlyAlertOnce，替换同一通知卡片。采用至少一次尝试，不声称跨数据库和系统服务的严格 exactly-once。所有重试入口串行化。系统调用成功不代表用户一定看见通知，勿扰/系统排序仍由 Android 决定。投递历史表随重复周期增长，目前未自动清理用户历史。

## 权限和系统限制

通知权限与精确闹钟权限相互独立。拒绝通知、关闭应用通知或关闭事项通知渠道时，记录保持 blocked，并显示中文原因。进入应用、返回权限设置或恢复调度时会再次检查授权，符合条件则补发。系统错误保留 failed，自动重试至少间隔一分钟。一次恢复超过三条积压提醒时，只显示一条摘要，完整事项保留在“错过提醒”中等待查看，避免通知洪泛。用户可以重试或确认已经知道；已成功投递/已确认的记录不反复重放。悬浮窗权限只影响桌宠和气泡。

Android 的“强行停止”会取消/阻止应用闹钟及广播，必须由用户重新打开应用后恢复；普通系统回收进程不等同于强行停止。设备关机期间无法提醒。厂商后台限制、Doze 配额和用户电池策略可能造成延迟，需要真机验证，不能以编译成功代替可靠性结论。

锁屏通知使用 `VISIBILITY_PRIVATE`，通知内容遵循系统锁屏隐私设置。备忘录不经网络发送，数据库位于应用私有目录。应用禁用 Android 自动备份。

## 备份、导入和数据库升级

备忘录页面通过 Android 系统文件选择器导出/导入 JSON；不请求存储目录的广泛访问权限。格式标识为 `CuteDog.Reminders`，`schemaVersion=1`，含事项字段、原时区、月度/当地时间锚、完成状态和稍后时间。导入逐项检查字段集合、严格整数/布尔类型、有效时区、日期范围（1970—2200）、标题/详情长度和重复规则。单份上限 2 MiB、5000 条；只要一条非法，整份不写入。

默认“合并”按完整事项内容去重，重映射源 ID，绝不因编号相同覆盖本地事项。预览显示条数和重复数量。只有用户明确选择“替换”并确认后，才清空当前事项；替换前在同一 SQLite 事务保存可恢复快照，包含全部原事项及投递历史。事务失败自动回滚。撤销替换会重建原数据关系，也会为撤销前的数据生成新快照。普通导出文件只含事项，私有撤销快照额外保留投递历史。提醒调度在成功提交后刷新。

数据库版本从 1 升至 2，使用 ALTER TABLE 增加待投递字段和索引，不删除原事项或原投递行。旧版记录因无法证实是否真正显示通知，被标为 `legacy`（送达状态未知），保留在历史中，不猜测为成功，也不突然重放全部旧记录。新版本产生的权限阻塞会被明确保存并重试。

可调用 `ReminderBackup.availableBackups()` 读取私有快照列表，`restoreBackup(id)` 撤销相应替换，`deleteBackup(id)` / `clearBackups()` 明确清理快照。删除事项不会自动删除早先保存的撤销快照。导入文件不携带可执行操作、不直接写原 ID，也不包含 API Key 或聊天内容。提醒文件仍包含用户私人事项，只应由用户自行选择保存位置。

## 自然语言草稿

`ReminderDraftParser.parse` 支持明确的“今天/明天/后天 + 钟点”，以及 `yyyy-MM-dd HH:mm`。例如“明天下午三点记得给老师发邮件”生成标题和时间草稿；必须在表单确认后保存。不明确、无事项内容、已经过去或不存在的日期返回 `null`，不猜测用户意图，不自动创建闹钟。这是本地日期解析能力，不冒充通用语言模型。

## 集成接口

```kotlin
val repository = ReminderRepository(context)
val scheduler = ReminderScheduler(context)
// 从 Dispatchers.IO 执行数据库与批量调度。
val id = repository.save(reminder)
repository.get(id)?.let(scheduler::schedule)

repository.setCompleted(id, true)
scheduler.cancel(id)

// 应用启动、从系统设置返回后恢复当前授权下的调度。
scheduler.restoreAll()
```

`com.cutedog.app.REMINDER_EVENT` 是限制到当前包的广播，携带 `reminder_id`、`title`、`message`。`com.cutedog.app.REMINDERS_CHANGED` 通知可见页面刷新。两个事件都不应让其他应用注册导出接收器。

## 测试与待验收项

源码包含 25 项日期/重复/草稿解析 JUnit 测试、15 项备份编解码 JUnit 测试及 13 项 Android 仪器测试。设备测试覆盖真实 SQLite CRUD、幂等/并发、稍后提醒、精确授权降级、真实闹钟→通知→通知按钮、通知拒绝后的持久化、恢复后实际投递与去重、积压摘要、原子备份合并/替换撤销、v1→v2迁移和1000条原生SQLite事务写入/索引读取性能。权限相关测试在前置条件不满足时明确跳过，需由宿主分别安排拒绝与允许权限阶段；不能在仪器进程内撤权导致测试进程被杀。

执行结果以根目录测试报告及本次 Gradle XML 为准，测试源码存在不等于已通过。设备上的通知触发时间、重启、强行停止、Doze、锁屏、通知按钮及各厂商后台策略需要单独验收。尤其需覆盖 API 26 与 35、拒绝/撤销通知权限、拒绝/撤销精确闹钟权限、31 日月度重复、夏令时跨越、提前提醒和重复事项稍后提醒。
